How the System Works (In Simple Words)

Amazon provides two distinct reports for the exact same payout: a horizontal CSV (Payments) where charges sit in columns, and a vertical TSV (Settlements) where each charge is a line item. The pipeline normalizes, maps, matches, and proves they describe the exact same money down to the cent.

1
Single-Table Ingestion
Ingests both raw files into a single unified table (unified_transactions), preserving raw payloads, line numbers, and file provenance.
2
Config-Driven Rules
Loads mapping CSVs into database tables. Dynamically evaluates record_ref join keys and routes charges by amount sign.
3
Reconciliation Engine
Groups multi-row granularity (1:N and N:1) by record_ref. Categorizes lines into Reconciled and Unreconciled.
4
Variance Detective
Traces root cause of initial discrepancies to faulty config rules and generates MAPPING_FIXES.sql.
5
Dual-Sheet Excel Export
Generates CFO-ready .xlsx with Sheet 1 (Summary) and Sheet 2 (Consolidated Data with row-by-row differences).
Database Schema Architecture

Mandatory architectural requirement: Ingest both files in a single table, not two different tables.

CREATE TABLE unified_transactions ( id SERIAL PRIMARY KEY, source_file VARCHAR(50) NOT NULL, -- 'AMAZON_PAYMENTS' or 'AMAZON_SETTLEMENTS' line_number INT NOT NULL, -- Source file line number for audit trail settlement_id VARCHAR(50), -- Payout settlement batch ID order_id VARCHAR(100), -- Amazon Order ID sku VARCHAR(100), -- Merchant SKU transaction_status VARCHAR(50), -- 'Released' or 'Deferred' raw_type VARCHAR(100), -- Original transaction type amount NUMERIC(15, 2) NOT NULL, -- Money amount record_ref VARCHAR(255), -- Dynamic +-joined reconciliation key summary_field VARCHAR(100), -- Target Summary Sheet category bucket raw_payload JSONB -- Complete unedited source row );

Genuine Mapping Defects Found & Fixed (Step 5 Core ⭐)

As required by the assignment, these genuine defects were traced to root cause and fixed cleanly via SQL updates in MAPPING_FIXES.sql without any hardcoded code tweaks.

1. Promotional Rebates Routed to 'expenses_other' Variance: $11,273.53

In payment_mapping_configs, ORDER promotional rebates were mapped to expenses_other instead of expenses_promotional_rebates, creating an $11,273.53 variance.

UPDATE payment_mapping_configs SET to_summary_field_when_positive_amount = 'expenses_promotional_rebates', to_summary_field_when_negative_amount = 'expenses_promotional_rebates' WHERE transaction_type = 'ORDER' AND amount_field = 'promotional_rebates';
2. Omission of Sales Tax on Refunds in Payments Config Variance: $42.59 (Bottom-line payout blocker)

In payment_mapping_configs, REFUND sales_tax_collected had empty routing (''). On the Settlement side, refund tax clawbacks were correctly routed to refunded_expenses.

UPDATE payment_mapping_configs SET to_summary_field_when_positive_amount = 'refunded_expenses', to_summary_field_when_negative_amount = 'refunded_expenses' WHERE transaction_type = 'REFUND' AND amount_field = 'sales_tax_collected';
3. Gift Wrap Credits Mapped to Non-Existent Summary Field Variance: $11.61

In payment_mapping_configs, ORDER gift wrap credits were routed to sales_gift_wrap_credits, which does not exist on the Summary sheet hierarchy. Settlement routes gift wrap to sales_other.

UPDATE payment_mapping_configs SET to_summary_field_when_positive_amount = 'sales_other', to_summary_field_when_negative_amount = 'sales_other' WHERE transaction_type = 'ORDER' AND amount_field = 'gift_wrap_credits';
4. Catch-All Rule Double-Counting 'total' Column Variance: Double-Count Prevention

In payment_mapping_configs, a fallback catch-all rule routed amount_field = 'total' to expenses_amazon_fees. In Payments CSV, 'total' is a horizontal row sum, not an independent expense.

UPDATE payment_mapping_configs SET to_summary_field_when_positive_amount = '', to_summary_field_when_negative_amount = '' WHERE amount_field = 'total';
5. Plural vs Singular Mismatch in record_ref Template Matching Join Key Defect

Payments had AWD_STORAGE_FEES (plural) while Settlements had AWD_STORAGE_FEE (singular), causing AWD fee lines to fail reconciliation matching.

UPDATE payment_mapping_configs SET record_ref = 'txn_ref+AWD_STORAGE_FEE+settlement_id+date' WHERE record_ref LIKE '%AWD_STORAGE_FEES%';
